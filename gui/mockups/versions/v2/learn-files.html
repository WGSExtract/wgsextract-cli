Your file journey

How tens of gigabytes of raw reads step down into a compact variant table, and why keeping aligned reads lets you re-run callers later.

FASTQ: unplaced reads straight from the sequencer

FASTQ (FASTA with Quality scores) holds raw DNA (deoxyribonucleic acid) reads before chromosome positions are assigned, storing each read’s name, bases and per-base quality string. Paired-end runs arrive as compressed R1 and R2 files (~30–100 GB total at 30×, such as the unassigned 2 × 38.5 GB pair in the library).

Alignment: placing every read on a reference map

Alignment maps reads onto a reference genome using Burrows-Wheeler Aligner tools (bwa, bwa-mem2 or bwa-mem3) for short reads or minimap2 for long reads. Realigning Gordon’s 38× genome onto GRCh38 (build 38) takes hours and heavy scratch space, and reads inside near-identical repeats still keep low mapping confidence.

BAM & CRAM: aligned reads ready to inspect

BAM (Binary Alignment Map) stores every read with its chromosome coordinate and qualities, taking 60–100 GB at 30–38× (71.2 GB for Alex; 92.4 GB for Gordon). CRAM (Compressed Reference-oriented Alignment Map) shrinks the same alignments to 16.8 GB on Reginald’s 31× genome by storing differences against the reference, so decoding a CRAM later requires that exact reference file.

Converting BAM to CRAM is lossless unless you turn on quality binning, which permanently coarsens per-base quality scores. Verify and back up a new CRAM before deleting a source BAM.

Variant calling: inferring genotypes from stacked reads

Variant callers (bcftools, Genome Analysis Toolkit / GATK, DeepVariant) weigh stacked reads to infer alleles, using models matched to your sequencing platform and the copy count of X, Y and mtDNA (mitochondrial DNA). Standard callers target single-base changes and short indels; structural changes and repeat expansions need specialized callers.

VCF & gVCF: compact variant tables

VCF (Variant Call Format) drops the reads and stores only coordinates, genotypes and quality scores. Helen’s 4.9 million DeepVariant calls fit in 148 MB, at the cost of no longer having reads to realign onto newer builds. A genomic VCF (gVCF) adds confidence blocks across non-variant stretches.

Treat any position missing from a variant-only VCF as unknown, never as reference (0/0). That site may match the reference, lack read coverage or have failed filtering. See Helen’s example in the next lesson.

Sidecar index files

An index (.bai/.csi for BAM, .crai for CRAM, .tbi/.csi for compressed VCF, .fai for FASTA) maps coordinates to file offsets so tools can jump straight to a gene without scanning the whole file. Keep each index beside its data file (Alex’s BAM is waiting on a missing index) and rebuild it if the file changes. Multi-gigabyte aligner indexes live separately in the reference library.

What to archive

  • Your BAM, CRAM or FASTQ if storage allows, since newer callers and lineage updates go back to the reads.
  • The exact FASTA (FAST-All) bundle name and checksum (~3 GB uncompressed) needed to decode any CRAM.
  • Your VCF or gVCF, its index and the run manifest recording which tool versions produced it.

Sorting or realigning a 70–90 GB genome also needs generous temporary space on an SSD (solid-state drive) while the job runs.

Exporting consumer DNA-test files

A consumer DNA-test file (~25 MB) lists genotypes at ~600,000 fixed chip markers. WGS Extract can export compatible 23andMe, AncestryDNA, MyHeritage and FamilyTreeDNA files from sequencing data, leaving uncovered sites blank. Conversion only goes one way: you cannot reconstruct whole-genome reads from a chip file. Before uploading an export to a matching site, read Privacy & sharing, since upload rules vary by service.

Hardware and software dependencies

Heavy runs lean on CPU (central processing unit) threads, fast disk and 16–32+ GB of RAM (random-access memory). A GPU (graphics processing unit) helps only tools built for it. On Windows x86-64, the optional wgse-bwa build uses NVIDIA CUDA automatically if the driver, RAM and Windows commit checks pass; otherwise it runs on CPU. Use --no-prefer-native-gpu (or prefer_native_gpu = false in config.toml) to force CPU. Parabricks is a separate Linux/Docker option.

WGS Extract checks for tools before starting. Tools on this computer shows what’s installed and which optional Pixi environments you can choose to add or remove.
