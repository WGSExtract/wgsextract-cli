Your file journey

How tens of gigabytes of raw reads step down into a compact variant table, and why keeping aligned reads lets you re-run callers later.

FASTQ: unplaced reads straight from the sequencer

FASTQ (FASTA with Quality scores) holds raw DNA (deoxyribonucleic acid) reads before chromosome positions are assigned, storing each read’s name, bases and per-base quality string. Paired-end runs arrive as compressed R1 and R2 files (~30–100 GB total at 30×, such as the unassigned 2 × 38.5 GB pair in the library).

Alignment: placing every read on a reference map

Alignment maps reads onto a reference genome using Burrows-Wheeler Aligner tools (bwa, bwa-mem2 or bwa-mem3) for short reads or minimap2 for long reads. Realigning Gordon’s 38× genome onto GRCh38 (build 38) takes hours and heavy scratch space, and reads inside near-identical repeats still keep low mapping confidence.

BAM & CRAM: aligned reads ready to inspect

BAM (Binary Alignment Map) stores every read with its chromosome coordinate and qualities, taking 60–100 GB at 30–38× (71.2 GB for Alex; 92.4 GB for Gordon). CRAM (Compressed Reference-oriented Alignment Map) shrinks the same alignments to 16.8 GB on Reginald’s 31× genome by storing differences against the reference, so decoding a CRAM later requires that exact reference file.

BAM-to-CRAM conversion is lossless unless quality binning is requested, though binned quality detail cannot be restored afterward. Verify and back up a new CRAM before deleting a source BAM.

Variant calling: inferring genotypes from stacked reads

Variant callers (bcftools, Genome Analysis Toolkit / GATK, DeepVariant) weigh stacked reads to infer alleles, using models matched to your sequencing platform and the copy count of X, Y and mtDNA (mitochondrial DNA). Standard callers target single-base changes and short indels; structural changes and repeat expansions need specialized callers.

VCF & gVCF: compact variant tables

VCF (Variant Call Format) drops the reads and stores coordinates, genotypes and quality scores: Helen’s 4.9 million DeepVariant calls fit in 148 MB, though without reads she cannot realign to newer builds. A genomic VCF (gVCF) adds confidence blocks across non-variant stretches.

Treat any position absent from a variant-only VCF as unknown rather than assuming reference (0/0). It may be reference, uncovered or filtered out. See Helen’s example in the next lesson.

Sidecar index files let tools jump straight to a gene

An index (.bai/.csi for BAM, .crai for CRAM, .tbi/.csi for compressed VCF, .fai for FASTA) maps coordinates to file offsets so tools jump straight to a gene. Keep it beside its data file (Alex’s BAM waits on a missing index) and rebuild it if the file changes; multi-gigabyte aligner indexes live separately under reference data.

Which files are worth keeping long term

  • Read files: archive your BAM, CRAM or FASTQ if storage allows, since future callers and lineage updates go back to reads.
  • Exact reference: record the FASTA (FAST-All) bundle name and checksum (~3 GB uncompressed) needed by any CRAM.
  • Calls and provenance: keep your VCF/gVCF, index and run manifest recording tool versions.

Leave generous free SSD (solid-state drive) scratch space before sorting or realigning a 70–90 GB genome.

Consumer DNA-test exports as a side branch

A DNA-test file (~25 MB) tables ~600,000 chip markers. WGS Extract can export compatible 23andMe, AncestryDNA, MyHeritage or FamilyTreeDNA tables from sequencing (leaving uncovered sites blank), though no kit can regenerate whole-genome reads and third-party upload rules vary. Check privacy trade-offs before uploading.

Hardware and software dependencies

Heavy runs lean on CPU (central processing unit) threads, fast disk and 16–32+ GB of RAM (random-access memory). A GPU (graphics processing unit) helps only supported callers, and NVIDIA CUDA (Compute Unified Device Architecture) builds differ from Apple Metal. Tools run via Docker or a Pixi environment, and WGS Extract verifies they are installed before starting.
