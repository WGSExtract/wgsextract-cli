Privacy & sharing

A genome is identifying data about you and, indirectly, your biological relatives.

Local analysis and network requests are different

In the app design, analysis runs on the computer hosting the WGS Extract server. A phone is a remote control for that computer, not a place the analysis runs. Choosing another server means trusting that computer with the inputs it can access.

This clickable mockup uses pretend genomes and simulated jobs, not your actual DNA. Its review server stores mockup notes; never put real genetic details into review notes or screenshots.

Downloading reference data still contacts a server

Reference genomes, annotation databases and tool images can be large downloads. A public-data download contacts its provider, which can see ordinary connection details such as your IP address. That is different from sending your variant positions or genotypes.

Ordinary analysis should not silently upload sample-derived information. Review any explicit online lookup or upload: what is sent, to whom, and why? Reading an external reference link also opens a website; internal Learn links stay in the mockup.

Share the smallest useful result, with consent

  • Ask what a recipient actually needs: a report, a region, or all the reads. A regional extract reveals less, but is still sensitive.
  • Removing your name does not make a genome anonymous. Filenames, read headers and report metadata can also identify people.
  • Before a matching-site upload, check acceptance rules, retention, research consent, relative matching and deletion policies.
  • Use access-controlled transfer and encrypted storage or backups. Do not post genetic files on public issue trackers.

Ask permission before analyzing or sharing another person's file. Unexpected family findings can affect people who never chose to be tested.
