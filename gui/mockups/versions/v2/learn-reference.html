Reference genomes

A coordinate only makes sense on the map it came from.

A shared map, not an ideal genome

A reference genome is a collection of named DNA sequences. Reads are aligned against it, and variants are described relative to it. Its sequences are commonly stored in a FASTA file.

No single sequence represents everyone's DNA equally well. Some regions are difficult to map because of repeats, highly variable alleles or sequence missing from the reference.

GRCh37, GRCh38 and T2T are different maps

  • GRCh37: Genome Reference Consortium human build 37 (2009). Many older files and marker resources use its coordinates. UCSC hg19 is closely related, not identical in every sequence.
  • GRCh38: build 38 (2013), correcting and adding sequence. Widely supported by current resources.
  • T2T-CHM13: the Telomere-to-Telomere CHM13 assembly fills many previously unresolved repeat-rich regions. CHM13 itself has no Y chromosome; some bundles add a separate complete HG002 Y.

There is no universally best choice for every downstream task. Use references supported by your tools and databases, and record the precise bundle and version. Merely changing “1” to “chr1” does not convert builds.

Coordinates can move — and counting conventions differ

Adding or correcting sequence shifts positions. A location in GRCh37 need not describe the same DNA at that number in GRCh38. A complete variant description includes the assembly, chromosome, position and allele change.

VCF positions count from 1. BED intervals count starts from 0 and exclude the end: BED 0 100 covers the first 100 bases. Mixing conventions creates one-base errors even within the same build.

Liftover is coordinate translation, not re-sequencing

Liftover uses a chain file of aligned blocks between assemblies to translate positions. The chain must match the source, destination and direction.

Some variants fail to map, map more than once, or need strand and allele changes. It cannot recover read evidence. Realigning original reads lets them find new placements on the new reference; that takes longer and can change which variants are called.

CRAM needs the exact reference, not a similar label

A CRAM can encode read bases as differences from reference sequence. To reconstruct them, the decoder needs matching sequence, usually verified by checksums.

hs37d5, hs38, hs38d1 and hs38DH identify different reference bundles. Extra decoys or alternative sequences can change read placement. Preserve the reference identity and checksum with your archive.

If identification is ambiguous, confirm it with the lab. A confident-looking filename is not enough.
