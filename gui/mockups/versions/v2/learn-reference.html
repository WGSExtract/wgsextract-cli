Reference genomes

Why Gordon’s 2009-era BAM and Reginald’s newer CRAM put the same gene at different coordinates, and why exact reference files matter.

A shared coordinate grid for human DNA

A reference genome stores standard chromosome sequences in a FASTA (FAST-All) file so labs and databases share one DNA (deoxyribonucleic acid) coordinate grid. Because it is stitched together from a small group of volunteer donors, reads from personal insertions or hyper-variable immune regions may have nowhere clean to map.

Major human assemblies: GRCh37, GRCh38 and T2T-CHM13

  • GRCh37 (Genome Reference Consortium human build 37, 2009) is used by consumer kits like Alex’s 23andMe file and older alignments like Gordon’s BAM (Binary Alignment Map). The University of California, Santa Cruz (UCSC) hg19 build uses the same autosomal coordinates, but adds chr prefixes and uses a different mitochondrial sequence.
  • GRCh38 (build 38, 2013) closed hundreds of gaps, added alternate versions of variable regions and backs current clinical tools; Reginald’s CRAM (Compressed Reference-oriented Alignment Map) and Helen’s VCF (Variant Call Format) both use GRCh38.
  • T2T-CHM13 (Telomere-to-Telomere CHM13, 2022) finished centromeres and long repeats end to end; because CHM13 carried two X chromosomes, complete bundles add donor HG002’s Y chromosome.

Choose the assembly that matches the callers and databases you plan to use. Renaming chromosome 1 to chr1 only changes contig names; it never converts coordinates between builds.

Coordinate shifts and 0-based vs 1-based files

Closing gaps between GRCh37 and GRCh38 shifted millions of downstream coordinates, so comparing Gordon’s GRCh37 file directly against Reginald’s GRCh38 file by position number lands on different DNA.

Formats also count differently inside one build: VCF starts at 1, whereas Browser Extensible Data (BED) starts at 0 and stops before the end number (BED 0 100 equals VCF bases 1–100).

Coordinate liftover versus realigning the reads

Liftover translates VCF or chip coordinates between builds in minutes using a directional chain file, but sites in reworked patches can fail to map or flip strands. Realigning the original reads (the job running on Gordon’s BAM) takes hours and places reads onto new sequence and decoys directly.

Why CRAM needs the exact reference bundle

CRAM omits bases matching the reference and checks an MD5 (Message-Digest Algorithm 5) checksum per chromosome before decoding, halting immediately if handed the wrong FASTA.

Several distinct bundles share the “GRCh38” name, including hs38, hs38d1 (needed by Alex’s BAM) and hs38DH, just as GRCh37 pipelines use hs37d5 (Gordon’s BAM). Each bundle adds its own decoy contigs to catch stray reads. Record the exact bundle name or checksum with any CRAM, and check the file header when a filename is vague.
