Reference genomes

Why Gordon’s 2009-era BAM and Reginald’s newer CRAM put the same gene at different coordinates, and why exact reference files matter.

A shared coordinate grid for human DNA

A reference genome stores standard chromosome sequences in a FASTA (FAST-All) file so labs and databases share one DNA (deoxyribonucleic acid) coordinate grid. Built from a mosaic of volunteer donors, it leaves stretches where personal insertions or hyper-variable immune regions have trouble mapping cleanly.

Major human assemblies: GRCh37, GRCh38 and T2T-CHM13

  • GRCh37 (Genome Reference Consortium human build 37, 2009) underpins consumer kits like Alex’s 23andMe file and older alignments like Gordon’s BAM (Binary Alignment Map). University of California, Santa Cruz (UCSC) hg19 shares its autosomal coordinates while differing on chr prefixes and early mitochondrial sequence.
  • GRCh38 (build 38, 2013) closed hundreds of gaps, standardized mitochondria and backs current clinical tools; Reginald’s CRAM (Compressed Reference-oriented Alignment Map) and Helen’s VCF (Variant Call Format) both use GRCh38.
  • T2T-CHM13 (Telomere-to-Telomere CHM13, 2022) finished centromeres and long repeats end to end; because CHM13 carried two X chromosomes, complete bundles add donor HG002’s Y chromosome.

Pick the assembly your callers and databases expect, and record its exact bundle name. Renaming 1 to chr1 never converts coordinates between builds.

Shifted addresses and zero-based versus one-based counting

Closing gaps between GRCh37 and GRCh38 shifted millions of downstream coordinates, so comparing Gordon’s GRCh37 file directly against Reginald’s GRCh38 file by position number lands on different DNA.

Formats also count differently inside one build: VCF starts at 1, whereas Browser Extensible Data (BED) starts at 0 and stops before the end number (BED 0 100 equals VCF bases 1–100).

Coordinate liftover versus realigning the reads

Liftover remaps VCF or marker coordinates in minutes via a directional chain file, though sites in rebuilt patches fail or flip strands. Realigning original reads (the job running on Gordon’s BAM) takes hours and places reads onto new sequence and decoys cleanly.

Why CRAM insists on the exact reference bundle

CRAM omits bases matching the reference and checks an MD5 (Message-Digest Algorithm 5) checksum per chromosome before decoding, halting immediately if handed the wrong FASTA.

“GRCh38” covers distinct bundles such as hs38, hs38d1 (needed by Alex’s BAM) and hs38DH, just as GRCh37 pipelines use hs37d5 (Gordon’s BAM), each adding extra decoy contigs to catch stray reads. Archive the exact bundle name or checksum and check the file header when a filename is vague.
