# WGS Extract 0.8.8

This release adds opt-in gVCF reference evidence across the variant callers,
multi-type `vcf call`, genotype imputation, local polygenic scores, ancestry
proportions and research-only ACMG classification. It runs DeepVariant natively
on Apple Silicon and Linux and adds GPU options for Clair3 and the Linux
aligners. Defaults now stay offline, and outputs go to a `wgse/` folder beside
your input files. The desktop app gets collapsible sections, a Jobs pane and a
visible users workspace.

## Changed

- **Defaults stay offline.** Analysis commands no longer fetch missing public
  data on their own: they name what is missing and ask you to rerun with
  `--download` (or set `allow_reference_downloads = true` in `config.toml`;
  `--no-download` overrides it). Download and install commands work as before.
  Installed launchers run Pixi with `--no-install --frozen` and refuse an
  incomplete runtime instead of falling back to another CLI on `PATH`. The
  desktop app checks for updates only when you ask. See
  [privacy.md](../privacy.md).
- **Outputs go beside your files.** Without `output_directory`, a command
  writes to a `wgse/` folder beside its main input (BAM/CRAM, else FASTQ, else
  VCF, else a raw microarray file), so the folder holding your data stays
  untouched. A run that leaves the folder it made empty removes it.
- **Temporary work stays in the temporary folder.** Commands make their
  scratch folders in `--tmp-dir` / `temp_directory` (a hidden folder in the
  output directory only when none is set), and a plain input VCF is no longer
  bgzipped and indexed beside itself.
- **The users workspace.** New installs keep `config.toml` in
  `~/wgs-extract` (`%USERPROFILE%\wgs-extract`), shared with the desktop app;
  an install with one in the per-user config folder keeps using it. The
  dataset library is now the My Genomes library (`mygenomes_library`, default
  `~/wgs-extract/mygenomes`); `dataset_library` and `--dataset-library` still
  work, and an existing `datasets/` folder beside the default reference
  library is renamed `mygenomes/`.
- Downloads use 41 more of this project's published mirrors (pinned by
  SHA-256) before the original sources. See
  [resource-mirrors.md](../resource-mirrors.md).
- CLI start-up is much faster (`--help` from about 690 to 80 ms), and
  `help --all --json` is a compact command index; `help <command> --json` has
  the full schema.

## New

- `vcf call` calls several variant types in one run: `--types snp,indel,sv,cnv`
  (any mix; default `snp,indel`) runs bcftools for SNPs and InDels and the
  `vcf sv` / `vcf cnv` callers, each into the VCF its own command writes.
  `--reference-evidence gvcf` writes SNPs and indels as one
  `bcftools.g.vcf.gz` instead, in one pass. `--merge` joins the parts by
  position into `variants.vcf.gz` (`variants.g.vcf.gz` with the gVCF, + `.tbi`)
  and removes them. SV and CNV calling stay Linux and macOS only.
- `vcf pharmcat` takes the bcftools gVCF that `vcf call --reference-evidence
  gvcf` writes: its variants are the calls and its depth-only blocks the
  reference evidence for absent PharmCAT sites, as for a gVCF found beside a
  variant VCF.
- Python API: quick read-only calls (`info`, `info chip`, `sample show`,
  `ref status`, `ref library-list`, `example-genome list`, `deps check`) can
  run on several threads at once, each with its own result, progress
  callback, cancel token and settings; other operations, and those asked to
  save files (`info --detailed`/`--format`, `ref library --list
  --remote-sizes`), still run one at a time. `with api.scoped_config(path):` gives one thread's calls their own
  `config.toml`. Cancelling a call now stops only its own tools. See
  [api.md](../api.md).
- `vcf acmg --research-acmg` adds automated ACMG/AMP classes from fastVEP
  (`ACMG_CLASS`, `ACMG_CRITERIA`, `ACMG_TRANSCRIPT`) to a `vep run` VCF, on the
  transcript the variant table shows. **Research use only; not a diagnosis**:
  it is off unless asked for, and every output carries the disclaimer. It
  refuses databases that lack any of its eight sources (ClinVar and its
  protein index, gnomAD v4.1 and its constraint, ClinGen, REVEL, SpliceAI,
  phyloP), which you build with `fastvep sa-build`. GRCh38; Linux and macOS,
  not Windows. See [acmg.md](../acmg.md).
- On a `vcf acmg` VCF, `vcf table` fills the columns `acmg_class`,
  `acmg_criteria` and `acmg_transcript` (empty otherwise) and records the
  research-only disclaimer in its metadata and manifest; `report` adds an
  **Automated ACMG classes (research only)** section, headed by the
  disclaimer, with the carried alleles' classes and the P/LP calls in the
  gene list's genes; and the desktop app runs `vcf acmg` once you tick that
  you understand it is research use only.
- `ref acmg-data` downloads those eight sources and the Ensembl GFF3 from
  their publishers, checks them against the checksums they publish, shows
  their terms (REVEL and SpliceAI are non-commercial) and builds the fastVEP
  databases into the library, where `vcf acmg` now finds them. gnomAD's 877 GB
  are streamed; `--chromosomes` builds part of the genome, `--dry-run` shows
  the sizes, and reruns resume. See [acmg.md](../acmg.md).
- `vcf snp` and `vcf indel` can also write reference evidence:
  `--reference-evidence gvcf` (or `reference_evidence = "gvcf"` in
  `config.toml`) adds `bcftools.g.vcf.gz` (+ `.tbi`), a gVCF of every assessed
  base, beside the unchanged variant VCF. A shared classifier tells confident
  reference from low-quality reference, coverage gaps, filtered and no-call
  bases, and ploidy-0 bases such as a woman's chrY. Off by default: it adds a
  second bcftools pass. See
  [reference-evidence.md](../reference-evidence.md).

- `vcf deepvariant --reference-evidence gvcf` (or the same `config.toml`
  setting) also writes `deepvariant.g.vcf.gz` (+ `.tbi`) from the same run, on
  the CPU (Google's image or `wgse-deepvariant`) and with Parabricks
  (`--gpu`); the variant VCF is unchanged. On HG002 chr20 it added about 15-20%
  to the run and 21 MB. `wgse-deepvariant` keeps the whole call set in memory
  to write it, so its preflight allows about 20 GiB for a whole genome (5
  without).

- `score pgs` and `vcf pharmcat` read a VCF's reference evidence: when the
  caller published a gVCF beside the VCF (found through its result manifest),
  a site the VCF doesn't list counts as reference only where the gVCF read it
  well; coverage gaps, low-quality, filtered and no-call bases stay missing
  (in PharmCAT, a no-call `--absent-to-ref` can't fill). A gVCF given to
  `score pgs` directly is now read the same way: its reference blocks and
  `0/0` records need enough depth and genotype quality, and haploid `0`
  blocks no longer block a site. On HG002 chr20 with PGS000018, matched sites
  rose from 12,723 to about 44,000. See
  [reference-evidence.md](../reference-evidence.md#commands-that-read-it).
- `vcf gatk --reference-evidence gvcf` writes `gatk.g.vcf.gz` (+ `.tbi`):
  HaplotypeCaller's gVCF, banded by GQ at 10, 20, 30 and 60 (about 1.4 GB a
  genome, against 6.5 GB with GATK's default bands), and the VCF genotyped
  from it by GenotypeGVCFs. Not with `--gpu` or `--scatter`.
  `vcf clair3 --reference-evidence gvcf` writes `clair3.g.vcf.gz` from the
  same run, on the CPU or the GPU; it is about 2.4x slower on the CPU and
  4.3x on the GPU, which the run warns about (in one 5 Mb measurement the
  CPU was faster than `--gpu` with the gVCF; a `--gpu` run's warning reports it). A man's haploid chrX and chrY are called apart from the rest,
  and their gVCF parts are cut at the partition edges and gathered in order.

- `wgse-deepvariant` 0.3.1 writes a gVCF PL value for every genotype, those
  with `<*>` included, as Google's image does; 0.3.0 left them out of variant
  records, which tools reading PL by genotype index would misread (#999).

- Low-memory Macs retain Metal BWA rather than the slower CPU fallback when
  compressed staging fits the existing physical-RAM gate. Alignment no longer
  overlaps duplicate marking/sorting; bounded compressed BAM checkpoints avoid
  large temporary consolidations. Whole HG00235x on the 16GB M1 matched all
  ordered SAM records in 6.44h including verification, with 0.073GiB swap-out
  and 42.31GiB minimum free disk. The explicit GPU speed preference still
  permits over-budget concurrent execution. See
  [the 16GB measurements](../apple-silicon-16gb.md#defaults-for-16-gb).

- **Genotype imputation:** `ref imputation` prepares the GRCh38 reference
  panel and `vcf impute` imputes genotypes with GLIMPSE2 for low-coverage
  reads or Beagle for chip genotypes. Imputed genotypes carry calibrated
  confidence labels that downstream commands show.
- Genotype imputation also works natively on **Windows x64**:
  `pixi install -e imputation` installs GLIMPSE2 2.0.1 from our `glimpse2-1`
  release (pinned by URL and SHA-256), Beagle and native OpenJDK.
  `ref imputation` prepares the GRCh38 panel; `vcf impute` imputes
  low-coverage reads or genotype-only VCFs with downstream imputed-call labels.
  No MSYS2 or WSL is needed at runtime. GLIMPSE2 phase requires AVX2/FMA;
  Windows ARM64, Linux ARM64 and Apple Silicon remain unsupported.
  See [imputation.md](../imputation.md).

- `score pgs` computes research-only local polygenic score sums from a VCF,
  with 11 curated PGS Catalog IDs, arbitrary IDs (with a warning), and custom
  scoring files. JSON, TSV and the manifest report missingness, licence and
  citation. Absent variants are never assumed reference without a confident
  BED or called gVCF block and indexed FASTA. For the 11 curated scores on
  GRCh38 it also places the score among the HGDP+1KG reference samples,
  adjusted for the sample's ancestry (the `pgs-ref-1` reference, 38 MB). It
  withholds the percentile, with a warning, when too few variants match or the
  ancestry projection is missing or outside the reference. See
  [pgs.md](../pgs.md).

- `qc ancestry` estimates admixture-style ancestry proportions from a BAM/CRAM,
  VCF or microarray raw-data file: 7 continental and 12 sub-continental
  reference components learned from the HGDP and 1000 Genomes samples in
  gnomAD, each with a 95% interval. They are proportions of reference
  populations, not an ethnicity. The personal report shows them. Install the
  16 MB reference with `ref ancestry --install`, or pass `--download`. See
  [docs/ancestry.md](../ancestry.md).
- `ref library --install` downloads genomes from copies in this project's
  GitHub releases first, checked against a pinned SHA-256, and falls back to
  the original source (NCBI, EBI, UCSC, AWS), which has been slow and flaky.
  See [docs/reference-genomes.md](../reference-genomes.md).
- `--aligner auto` on Apple Silicon can now pick bwa-mem2 when
  `wgse-bwa-mem2` 0.5.0 or later is installed, without upstream bwa-mem2 or
  the reference's `.0123` file, using its smaller memory estimate. bwa-mem2's
  records differ from bwa's, so a run that used to align with bwa (or
  `wgse-bwa`) may now give a different BAM; pass `--aligner bwa` to keep bwa.
- `vcf deepvariant` runs DeepVariant natively on Apple Silicon Macs with
  `wgse-deepvariant`, WGS Extract's build of DeepVariant 1.10.0 (the
  `macos-deepvariant` release, 0.1.1 or later): no Docker, call_variants on
  the GPU, and the same PASS calls, genotypes and filters as Google's x86-64
  image (HG002 chr20 in about 5 minutes on an M1 Pro; HG003's whole genome in
  2 h 42 min with every hap.py count identical to Google's and two QUAL-0
  RefCalls differing; 16 GB Macs fit). Put it on `PATH` and set the
  new `deepvariant_weights` setting in `config.toml` to its weights folder,
  whose files are checked against their published hashes; only the WGS model
  is qualified. `deepvariant_native = "off"` keeps the Docker image instead.
  See [native/deepvariant/README.md](../../native/deepvariant/README.md).
- `vcf deepvariant` also runs `wgse-deepvariant` on Linux x86-64 (0.3.1, the
  new `linux-deepvariant` conda packages): DeepVariant 1.10.0's WGS and
  ONT_R104 models without Docker, on the CPU, or with `--gpu` on an NVIDIA
  GPU through CUDA instead of Parabricks (call_variants for HG002 chr20 in 20 s on an RTX 3090,
  against 79 s for Google's GPU image and 15 minutes for its CPU image on 4
  threads), with the same sites,
  genotypes and filters as Google's image; on HG002's ONT chr20, 2 of 387,476
  sites differ, outside GIAB's confident regions. With it installed, `--gpu`
  uses it for both models; `deepvariant_native = "off"` keeps Parabricks.
  Other models keep Google's image and Parabricks. Its weights
  (`wgse-deepvariant-weights-1.10.0`) are a separate download.
- `pixi install -e deepvariant` installs `wgse-deepvariant` 0.3.1's CUDA build
  on Linux x86-64 into an opt-in Pixi environment, where `vcf deepvariant`
  finds it.

- `wgsextract ref dense-sa` builds `wgse-bwa`'s optional dense suffix-array
  file for a reference (0.80 GB for hs38; `--list` and `--delete` too), and
  `align`/`realign` read it with `--dense-suffix-array` or
  `dense_suffix_array = true` in `config.toml`: the same alignments, about 11%
  faster on the CPU and 8% on the GPU, with the file held in RAM. It is never
  used unless asked; otherwise runs pass `wgse-bwa --dense-sa off`. Needs
  `wgse-bwa` 0.11.0 or later. See docs/hardware.md.

- `vcf snp` and `vcf indel` are about a fifth faster on Apple Silicon Macs
  with `wgse-mimalloc`, WGS Extract's build of the mimalloc allocator, which
  is now included in the default Pixi environment on Apple Silicon (published
  as [wgse-mimalloc-1](https://github.com/WGSExtract/wgsextract-cli/releases/tag/wgse-mimalloc-1),
  pinned by URL and SHA-256). They inject it into bcftools: the same records
  (5M read pairs: 102 against 132 s for SNPs, 155 against 193 s for indels). The new
  `mimalloc` setting and `--mimalloc off` turn it off; the manifest's
  `bcftools_allocator` metric says which allocator ran. See
  [hardware.md](../hardware.md#bcftools-with-mimalloc).

- `vcf clair3 --gpu` runs Clair3 2.0.5 on an NVIDIA GPU from HKU's CUDA
  image (pinned by digest; `clair3_gpu_image` in `config.toml`) on x86-64
  Linux, checking the driver, Docker's NVIDIA runtime and 7.8 GiB of free GPU
  memory first. CPU stays the default.
- `vcf deepvariant --gpu` (Parabricks) now calls whole genomes: it calls the
  diploid and haploid regions in separate runs and gathers them in reference
  order.
- DeepVariant, Clair3 and GATK apply sex- and PAR-aware ploidy, as bcftools
  already did: a man's chrX outside the PARs and chrY are called haploid.
- Linux aligners: `align` and `realign` use `wgse-bwa` (with its CUDA
  backend on x86-64, and on ARM64), `wgse-bwa-mem3` and Bioconda's
  `bwa-mem3 --compat` as stand-ins for bwa and bwa-mem2, and `wgse-minimap2`
  with its CUDA backend for long reads, from the `linux-aligners` releases.
  `bwa-mem3 --compat` goes first where it is installed and fits, since it was
  the fastest on the CPU. A `bwa-mem3` that crashes on glibc 2.44 is refused
  with an error naming the cause.
- `align` and `realign` take `--output-profile archive|calling` (or
  `output_profile` in `config.toml`) for smaller lossless CRAM output; the
  default is unchanged.
- `vcf snp` and `vcf indel` take `--baq` (or `baq = true`) for bcftools'
  heuristic base alignment quality. It is off by default and needs bcftools
  1.13 or later.
- `realign`, `vcf deepvariant` and `vcf clair3` print the disk, RAM and time
  a whole-genome run needs before starting, and refuse when the computer lacks
  the disk or RAM; `--no-preflight` runs anyway. `vcf clair3` also checks the
  temporary space its GPU mode needs.
- `vep download --assembly T2T-CHM13v2.0` builds a vep-rs cache from
  Ensembl's CHM13 gene set, and `vep run` annotates CHM13 VCFs with it.
- `lineage mt-haplogroup` classifies chrM from CHM13 alignments by mapping it
  onto the rCRS, and refuses other rotated chrM sequences instead of reporting
  a wrong haplogroup.
- `vcf sv` gives PacBio reads detected from their read groups pbsv or
  Sniffles by default, as `--pacbio` does, instead of Delly.
- Native Windows tools move to `windows-tools-9`, with faster bwa, samblaster
  and bcftools.

- config.toml is checked against one schema of every setting's type, range
  and choices when it loads: an out-of-range port or job count, or a value
  that isn't one of a setting's choices (such as `server_mcp_transport` or
  `microarray_quirks`), stops the run with an error naming the setting,
  where before the command that used it failed later or ignored it.
  [configuration.md](../configuration.md) lists every setting and is
  generated from that schema. Developer and test settings
  (`real_genome_test_path`, `real_genome_tests_enabled`, `pet_*`, and
  `dev_download_cache[_ttl_seconds]`, now `download_cache[_ttl_seconds]`)
  moved into a `[dev]` table; a config.toml that still has one at the top
  level fails to load and says where it goes.

## Fixes

- `vcf gatk` reads CRAMs whose `.crai` htsjdk refuses, such as the 1000
  Genomes CRAMs' (#1034): their unmapped-slice rows give the read length as a
  span. GATK failed at once; it now gets a fresh index built in the run's temp
  folder (seconds to minutes), and the CRAM and its index are left unchanged.
  A GATK failure on CRAM input now names htsjdk's own error instead of blaming
  CRAM 3.1, which it mentions only for CRAM 3.1 files.
- `align` and `realign` no longer admit an over-budget `wgse-bwa` GPU plan
  just because the CPU estimate is also oversized. Native BWA GPU selection
  now respects physical RAM less OS headroom without penalizing large-RAM
  hosts for momentarily low available memory; when
  it falls back to CPU, an also-over-budget sort is capped at 256M per thread.
  Smaller or already fitting CPU requests are retained. Workers and fixed
  K100M are unchanged for alignment identity. CPU fallback can be much slower
  than older GPU measurements; this addresses the excessive swap traffic on
  16 GB Macs tracked in #747 (low-memory realignment). The same whole HG002
  35x run retained every ordered record and reduced swap-out from 1,116.92
  to 47.87 GiB (95.7%), but alignment took 13.63 h rather than 5.40 h:
  reduced SSD swap traffic, not swap-free execution or a speed improvement.
  `--prefer-native-gpu` (or config `prefer_native_gpu = true`) opts into GPU
  speed only after normal GPU sort step-down fails: explicit memory is retained,
  while default/config memory is capped at 256M, subject to general sort limits.
  `--no-prefer-native-gpu` overrides config. Fallback messages name
  the roughly 2.5× measured slowdown and this override. Manifest/resume
  diagnostics retain the backend reason, estimate/budget bytes and requested/
  actual sort memory.
  The whole Metal/sort256 comparison kept the gold records at 5.08 h, but
  swap-out was still 378.39 GiB (versus CPU's 47.87 GiB), failing the 200 GiB
  gate. CPU therefore remains the low-memory default when no GPU plan fits.
  An ineffective speed preference no longer changes the reason or reruns a
  completed GPU alignment.

- Runs stopped with Ctrl-C or SIGTERM report `cancelled`, rather than `failed`,
  when a cleanup failure replaces the stop-signal handler's exit (#717).
- `align` refuses paired FASTQs whose read names or counts differ, and checks
  the aligned primary read count before publishing, instead of silently
  losing reads. Long-read FASTQs are detected from their content before the
  alignment defaults are chosen, even when renamed.
- A `--region` list too long to be a file name no longer crashes with "File
  name too long" (#977).
- The callers' sex check reads the alignment with its reference, so a CRAM
  whose header names a reference that no longer exists (such as 1000 Genomes'
  CRAMs) no longer falls back to the female ploidy. Sex inference is
  normalized, and an Unknown sex is refused rather than called as female.
- Native DeepVariant decodes CRAMs whose header reference is missing, using
  a local reference cache.
- Microarray exports no-call sites without confident evidence (depth 10, GQ
  20, PASS) by default, keep rCRS chrM coordinates, never pick the first of
  several liftover placements, and rebuild reused targets when the sex or a
  resource changes.
- ClinVar matching normalizes alleles against the reference and recovers
  phased MNVs; the report uses known cis/trans phase for a gene's recessive
  status. PharmCAT keeps reference evidence and shows ambiguous diplotypes;
  CYP2D6 reports the combined CYP2D6/CYP2D7 copy number and withholds
  ambiguous calls; weak recessive STR calls and unassessed parental
  inheritance stay unresolved; filtered or ambiguous Y-haplogroup evidence is
  refused.
- A gVCF reference block without `MIN_DP` has unknown depth and no longer
  counts as confident reference.
- Resumed steps rerun when files inside a directory input (such as VEP's
  cache) change. The report shows a newer failed attempt beside older
  evidence.
- A vcf annotator's missing resource file is a usage error naming the option,
  with a failed manifest. Genome builds are no longer inferred from a parent
  folder's name.
- Shared reference library locks respect the umask.

## Desktop app

- **Collapsible sections:** in Advanced mode each titled section starts
  collapsed to its header row and opens with the arrow on the right; the
  Inputs and Library Paths sections stay open.
- **Variant Calling** has **SNP**, **InDel**, **SV** and **CNV** checkboxes
  and one **Default** button, which runs `wgsextract vcf call` for the checked
  types. **gVCF** writes SNPs and InDels as one gVCF (also for GATK and
  DeepVariant), and **Merged** combines everything into one VCF.
- **Jobs pane:** the command output pane's first tab lists every job run this
  session, with its outcome, start time and main input; click one to open its
  tab. Hiding the pane keeps the row of job tabs.
- **Users workspace:** the app's own copy of the bundle, its state and run
  logs go back to the app's data folder. `~/wgs-extract` is now the users
  workspace: the settings file and the folders you manage (My Genomes,
  Reference Data, Reference Genomes, temporary files). Settings' **Users
  Workspace Location** moves it, and changing one of its folders asks whether
  to move what is in it. The 0.8.5 to 0.8.7 workspace becomes the users
  workspace on the first start, keeping its files.
- The Output Directory is unset by default, so outputs go to `wgse/` beside
  your input files; only Advanced mode can set it.
- Datasets is now **My Genomes**. Pages are reorganized: a **Haplogroup
  Analysis** section on Ancestry, an **Analysis** section on FASTQ, and
  Advanced-only refinements on Microarray, with sections renamed to say what
  they do.
- The app runs `wgsextract` commands directly instead of its own wrapper
  scripts (reference genome lists and deletes, test genomes, Unalign to FASTQ,
  FastQC, coverage status).
- Missing public data is downloaded only after you allow it: per run on the
  Lineage and Microarray pages, or with **Allow missing public-data
  downloads** in the advanced settings. The app checks for updates only from
  **Check for Updates…**.
- **Research-only ACMG classes** run once you tick that you understand they
  are research use only.
- The rest of the GUI for CLI name goes: the app calls itself WGS Extract GUI
  throughout, and its window layout resets once.
