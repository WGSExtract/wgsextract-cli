# WGS Extract 0.8.7

This release adds sample QC (relatedness and contamination), SMA carrier
screening and SV population frequencies, makes vep-rs the default VEP engine,
and has the desktop app offer to install a missing reference genome before a
run instead of failing.

## New

- **`qc relate`** checks sex, relatedness and continental ancestry across
  BAMs, CRAMs and VCFs with somalier: same person, parent-child, siblings,
  2nd and 3rd degree, with warnings for a sex or PED mismatch (swapped
  files). `ref somalier --install` gets its sites and the 1000 Genomes
  sketches. Linux and macOS (`pixi install -e somalier`);
  [docs](../relate.md)
  ([#614](https://github.com/WGSExtract/wgsextract-cli/issues/614)).
- **`qc contamination`** estimates DNA from another person (FREEMIX) in a
  GRCh37 or GRCh38 BAM or CRAM with VerifyBamID2. Above
  `qc_max_contamination` (default 0.03), variant calling, microarray and
  lineage warn, confidence labels are capped at moderate and the personal
  report says so. Linux and macOS; [docs](../contamination.md)
  ([#616](https://github.com/WGSExtract/wgsextract-cli/issues/616)).
- **`typing smn`** calls SMN1/SMN2 copy number with SMNCopyNumberCaller for
  SMA carrier status, flagging a possible silent carrier (g.27134T>G). It
  needs short-read WGS at 30x or more, runs from the `smn` environment (Linux
  and macOS), and is not a diagnosis. The report gains a carrier screening
  section ([#619](https://github.com/WGSExtract/wgsextract-cli/issues/619)).
- **`vcf sv-freq`** annotates structural variants with population
  frequencies from gnomAD-SV (GRCh38 and GRCh37) and gnomAD-LR (GRCh38),
  installed with `ref gnomad-sv --install`. `vcf table` gains `sv_af` and
  `sv_freq` columns, and the report lists rare SVs; [docs](../sv-frequency.md)
  ([#618](https://github.com/WGSExtract/wgsextract-cli/issues/618)).
- **vep-rs is the default VEP engine**, on every platform including Windows.
  On a whole HG002 genome it took 175 s instead of Ensembl VEP's 3.5 hours,
  with ≥99.9999% matching consequences. `vep download --engine vep-rs` builds
  its cache; `--engine ensembl` (or config `vep_engine`) keeps Ensembl VEP,
  and a setup with only an Ensembl VEP cache keeps using it, with a warning;
  [docs](../vep-engines.md)
  ([#602](https://github.com/WGSExtract/wgsextract-cli/issues/602)).
- **`typing str` on Nanopore and PacBio reads** uses LongTR (`longtr`
  environment), or STRkit with `--caller strkit`; short reads keep
  ExpansionHunter ([#615](https://github.com/WGSExtract/wgsextract-cli/issues/615)).
- **`vcf clair3`** uses Clair3 2.0.5 and now runs on Linux ARM64 and Apple
  Silicon as well as Linux x86-64
  ([#613](https://github.com/WGSExtract/wgsextract-cli/issues/613)).
- **`vcf pharmcat` on native Windows**
  ([#622](https://github.com/WGSExtract/wgsextract-cli/issues/622)).
- **`ref needs -- COMMAND`** lists the reference genome or annotation data a
  command line needs that the library lacks, with the command that installs
  each. The desktop app uses it to ask before a run.
- `--aligner auto` on Apple Silicon can now pick bwa-mem2 when
  `wgse-bwa-mem2` 0.5.0 or later is installed, without upstream bwa-mem2 or
  the reference's `.0123` file, using its smaller memory estimate. bwa-mem2's
  records differ from bwa's, so a run that used to align with bwa (or
  `wgse-bwa`) may now give a different BAM; pass `--aligner bwa` to keep bwa.
- `vcf snp` and `vcf indel` start the longest contigs first, so chrX no
  longer runs alone at the end: about 5% faster, with the same records
  ([#646](https://github.com/WGSExtract/wgsextract-cli/issues/646)).
- `methylation pileup` on a CRAM without `--region` only walks the contigs
  that have reads: 8 s instead of 190 s on a 1 Mb slice
  ([#611](https://github.com/WGSExtract/wgsextract-cli/issues/611)).

## Fixes

- `info` on a CRAM whose reference isn't installed reported 0 bp reads,
  single-end and an unknown sequencer. It now reports those as "Could not
  compute" and warns which reference to install.
- CRAM reads are never decoded with a reference fetched from the internet:
  every tool gets a local-only `REF_PATH`, so a CRAM whose `UR` file is gone
  uses the library's genome or fails, instead of silently downloading it from
  EBI ([#636](https://github.com/WGSExtract/wgsextract-cli/issues/636)).
- Chunked `realign` of a CRAM keeps every unplaced read; with htslib before
  1.25 some were dropped
  ([#655](https://github.com/WGSExtract/wgsextract-cli/issues/655)).
- BAMs whose read groups name several platforms (for example ONT and
  Illumina merged) no longer silently get short-read defaults: `align`,
  `realign`, `vcf deepvariant` and `vcf sv` refuse them unless an option
  chooses the platform
  ([#652](https://github.com/WGSExtract/wgsextract-cli/issues/652)).
- `vcf deepvariant` on Apple Silicon refuses Google's amd64 image up front
  (it can't run under emulation) and names the alternatives
  ([#665](https://github.com/WGSExtract/wgsextract-cli/issues/665)).
- `vcf clair3` reads CRAM 3.1, shows Clair3's own errors, and works when a
  path has a space; so does `vcf phase` with LongPhase
  ([#604](https://github.com/WGSExtract/wgsextract-cli/issues/604),
  [#623](https://github.com/WGSExtract/wgsextract-cli/issues/623),
  [#632](https://github.com/WGSExtract/wgsextract-cli/issues/632)).
- `methylation pileup` explains modkit's CRAM crash instead of failing with
  a bare segfault
  ([#608](https://github.com/WGSExtract/wgsextract-cli/issues/608)).
- The UCSC liftOver chains are checksum-pinned and fall back to a GitHub
  mirror when UCSC is unreachable
  ([#667](https://github.com/WGSExtract/wgsextract-cli/issues/667)).
- The `--metal` aligners fall back to the CPU when a GPU command hangs
  ([#548](https://github.com/WGSExtract/wgsextract-cli/issues/548)).
- Windows: the CLI and the app work from any install folder and Pixi home
  (`PIXI_HOME`), and a missing tools environment gives a clear error instead
  of every page failing with exit 127.
- Installing hs37d5 from the NIH mirror works again. NIH serves it as RAZF, an
  older indexed gzip that was taken for BGZF, so indexing failed and the install
  fell back to the much slower EBI mirror. It is now recompressed to BGZF.
- `ref bootstrap` no longer downloads the AADR v66.p1 2M SNP panel: the Harvard
  Dataverse server is slow enough to stall setup. Install it when you need it with
  `wgsextract ref aadr --install`, or from the app's Reference Data page. The
  Microarray page's **2M** format stays disabled, with a tooltip, until it is installed.

## Desktop app

- **Missing reference data:** running Info, variant calling, extraction and
  the rest on a CRAM whose reference genome isn't installed (for example
  hs37d5) no longer runs and reports nothing. A dialog names what is missing
  and offers **Install and Continue**, **Continue** or **Cancel**; the VCF
  annotation actions do the same for their annotation data.
- **The app's own data moves** to a `WGSExtract-gui` folder in the platform's
  app data folder, and setup installs the CLI there, so the workspace holds
  only your files and moving it no longer reinstalls the CLI. On the first
  start, a 0.8.6 install's settings come over and setup is offered again.
- WGSExtract's `config.toml` moves from `<workspace>/settings/` to the
  workspace folder itself (`~/wgs-extract/config.toml` by default). Existing
  files move on the next start.
- The app's executable is named `wgsextract-gui` on every platform.
- Linux AppImage: setup and actions no longer run with the AppImage's
  library paths, which broke setup on newer systems such as Ubuntu 26.04.
- Windows: saving settings no longer fails with `EPERM` when another program
  (the CLI, a virus scanner) has the file open for a moment.
- Layout, icon and error-state fixes across the pages, in light and dark
  mode and narrow windows.
- The AADR 2M SNP panel is an optional Reference Data download again, and
  the Microarray formats have tooltips for Consumer Tests, Reich Lab and AADR.
- The app site is now "WGS Extract GUI", with a
  [What's Different](https://wgsextract.github.io/wgsextract-cli/app/whats-different.html)
  page.

See the app's [CHANGELOG](https://github.com/WGSExtract/wgsextract-cli/blob/v0.8.7/gui/docs/CHANGELOG.md) for details.
